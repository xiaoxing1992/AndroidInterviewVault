# 跨进程传递大图片

## 问题

> Binder 能传多大数据？大图片怎么跨进程传递？有哪些方案？

## 核心答案

Binder 单次传输上限约 1MB，直接传大图片会抛 TransactionTooLargeException。三种方案：① 文件路径 + FileProvider（最常用，Binder 只传路径字符串）② ContentProvider + ParcelFileDescriptor（fd 通过 Binder 传递，接收方用 fd 读取）③ SharedMemory 共享内存（零拷贝，fd 通过 Binder 传递，接收方 mmap 映射同一块物理内存）。核心思路都是：图片数据不经过 Binder，Binder 只传"句柄"（路径/fd）。

## 深入解析

### 原理层（源码级）

**为什么不能直接用 Binder 传？**

```
Binder 传输限制：单次约 1MB（BINDER_VM_SIZE = 1MB - 8KB）

一张 1080p 图片的大小：
  1920 × 1080 × 4 bytes (ARGB_8888) ≈ 8MB

直接传会怎样？
  → TransactionTooLargeException
  → "data parcel size XXXXX bytes"
```

### 方案一：文件路径 + FileProvider（最常用）

```kotlin
// 发送方
fun sendImage(uri: Uri, intent: Intent) {
    // ① 把图片写入缓存文件
    val file = File(context.cacheDir, "shared_image.jpg")
    contentResolver.openInputStream(uri)?.use { input ->
        file.outputStream().use { output -> input.copyTo(output) }
    }

    // ② 通过 FileProvider 获取 content:// URI
    val contentUri = FileProvider.getUriForFile(context, authority, file)

    // ③ 通过 Intent 传递 URI（几十字节，Binder 轻松传递）
    intent.putExtra(Intent.EXTRA_STREAM, contentUri)
    intent.addFlags(Intent.FLAG_GRANT_READ_URI_PERMISSION)
}

// 接收方
fun receiveImage(intent: Intent) {
    val uri = intent.getParcelableExtra<Uri>(Intent.EXTRA_STREAM)
    uri?.let {
        // ④ 通过 ContentResolver 读取图片
        val bitmap = contentResolver.openInputStream(it)?.use { stream ->
            BitmapFactory.decodeStream(stream)
        }
    }
}
```

```
FileProvider 配置：
  <provider
      android:name="androidx.core.content.FileProvider"
      android:authorities="${applicationId}.fileprovider"
      android:exported="false"
      android:grantUriPermissions="true">
      <meta-data
          android:name="android.support.FILE_PROVIDER_PATHS"
          android:resource="@xml/file_paths" />
  </provider>

file_paths.xml:
  <paths>
      <cache-path name="shared" path="." />
  </paths>
```

```
原理：
  → 图片写入文件（磁盘/缓存目录）
  → Binder 只传 content:// URI（几十字节）
  → 接收方通过 ContentResolver 读取文件
  → 安全：FileProvider 授权机制，只有被授权的 App 能访问
```

### 方案二：ContentProvider + ParcelFileDescriptor

```kotlin
// 发送方 — 自定义 ContentProvider
class ImageProvider : ContentProvider() {
    override fun openFile(uri: Uri, mode: String): ParcelFileDescriptor {
        val file = File(context!!.cacheDir, "shared_image.jpg")
        // 返回文件描述符，可以跨进程传递
        return ParcelFileDescriptor.open(file, ParcelFileDescriptor.MODE_READ_ONLY)
    }

    override fun onCreate() = true
    override fun query(...) = null
    override fun getType(uri: Uri) = "image/jpeg"
    override fun insert(...) = null
    override fun delete(...) = 0
    override fun update(...) = 0
}

// 接收方
fun loadImage(contentUri: Uri) {
    // 通过 ContentResolver 获取 ParcelFileDescriptor
    contentResolver.openFileDescriptor(contentUri, "r")?.use { pfd ->
        // 用文件描述符读取图片
        val bitmap = BitmapFactory.decodeFileDescriptor(pfd.fileDescriptor)
    }
}
```

```
原理：
  → ContentProvider.openFile() 返回 ParcelFileDescriptor
  → ParcelFileDescriptor 包含文件描述符（fd）
  → fd 通过 Binder 传递（Binder 驱动自动翻译 fd，两个进程的 fd 值不同但指向同一文件）
  → 接收方用 fd 读取文件内容
  → 不拷贝图片数据，只传 fd
```

### 方案三：SharedMemory 共享内存

```kotlin
// 发送方
fun sendLargeBitmap(bitmap: Bitmap) {
    // ① 把 Bitmap 像素数据写入共享内存
    val byteCount = bitmap.byteCount
    val sharedMemory = SharedMemory.create("image_data", byteCount)
    val buffer = sharedMemory.mapReadWrite()
    bitmap.copyPixelsToBuffer(buffer)
    SharedMemory.unmap(buffer)

    // ② SharedMemory 实现了 Parcelable，通过 Binder 传递 fd
    val bundle = Bundle()
    bundle.putParcelable("shared_memory", sharedMemory)
    intent.putExtra("data", bundle)
}

// 接收方
fun receiveLargeBitmap(intent: Intent) {
    val sharedMemory = intent.getBundleExtra("data")
        ?.getParcelable<SharedMemory>("shared_memory")

    sharedMemory?.let {
        // ③ 用 fd mmap 映射同一块物理内存
        val buffer = it.mapReadOnly()
        val bitmap = Bitmap.createBitmap(width, height, Bitmap.Config.ARGB_8888)
        bitmap.copyPixelsFromBuffer(buffer)
        SharedMemory.unmap(buffer)
    }
}
```

```
原理：
  → SharedMemory 底层是 Ashmem（匿名共享内存）
  → 写入 Bitmap 像素数据到共享内存
  → 通过 Binder 传递 fd（不是像素数据，只有几十字节）
  → 接收方用 fd mmap 映射同一块物理内存
  → 零拷贝，两个进程直接读写同一块物理内存
```

```
SharedMemory vs Ashmem：
  Ashmem → Android 底层的匿名共享内存机制（C/C++ 层）
  SharedMemory → Android 8.0+ 的 Java 封装（推荐使用）
  两者底层是同一个东西
```

### 三种方案对比

```
方案                    传递内容          拷贝次数    复杂度    适用场景
──────                 ──────────       ────────   ──────   ────────
文件路径+FileProvider   content:// URI    0（读文件）  简单     最常用，通用
ContentProvider+fd     文件描述符 fd      0          中等     标准 Android 方式
SharedMemory           共享内存 fd        0          较高     高频传递，大图片
Bundle 直接传 Bitmap    像素数据          1（序列化）  简单     ❌ 超过 1MB 会崩溃
```

### 实战层（项目经验）

**为什么 Bitmap 直接放 Bundle 会崩溃？**

```kotlin
// ❌ 错误：直接传 Bitmap
intent.putExtra("bitmap", largeBitmap)
// Bitmap 实现了 Parcelable
// 序列化后像素数据写入 Parcel
// 超过 1MB → TransactionTooLargeException

// Bitmap.writeToParcel() 内部：
public void writeToParcel(Parcel p, int flags) {
    if (!mRecycled) {
        // 把像素数据写入 Parcel
        // 1080p 图片 ≈ 8MB → 超过 Binder 限制
        nativeWriteToParcel(mNativePtr, p);
    }
}
```

**Bitmap 压缩后能传吗？**

```kotlin
// 如果压缩后 < 1MB，可以传
val stream = ByteArrayOutputStream()
bitmap.compress(Bitmap.CompressFormat.JPEG, 80, stream)
val bytes = stream.toByteArray()
if (bytes.size < 1024 * 1024) {
    intent.putExtra("image_bytes", bytes)  // 可以，但不推荐
}
// 问题：压缩/解压有 CPU 开销，图片质量下降
// 推荐：还是用文件路径或 SharedMemory
```

## 记忆锚点

大图片跨进程的核心思路：图片数据不走 Binder，Binder 只传"句柄"。三种句柄：文件路径（最简单）、fd（ContentProvider）、共享内存 fd（零拷贝最高效）。超过 1MB 直接用 Bundle 传 Bitmap 必崩。
