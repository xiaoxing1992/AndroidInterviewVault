# 静态广播与动态广播详解

## 问题

> 静态广播和动态广播有什么区别？底层注册和派发机制是怎样的？Android 8.0 为什么要限制静态广播？无序广播和有序广播有什么区别？

## 核心答案

静态广播在 AndroidManifest.xml 中声明，由 PMS 在安装时解析注册到 AMS，App 未启动也能接收；动态广播在代码中 registerReceiver() 注册到 AMS，必须反注册否则泄漏。Android 8.0 限制了大部分隐式广播的静态派发（避免唤醒大量 App 浪费资源），显式广播和少数系统广播不受限。无序广播并行派发不可拦截，有序广播按 priority 串行派发可拦截可传数据。广播 onReceive 运行在主线程，10 秒内必须返回。

## 深入解析

### 原理层（源码级）

#### 广播派发完整流程

```
发送广播：
  sendBroadcast(intent)
    → ContextImpl.sendBroadcast()
      → AMS.broadcastIntent()
        ↓
AMS 处理：
  ① 权限检查
  ② 收集静态注册的 Receiver（从 PMS Manifest 解析）
  ③ 收集动态注册的 Receiver（从 AMS ReceiverList 查找）
  ④ 合并去重
  ⑤ 逐个派发
        ↓
派发方式：
  ├─ 静态 Receiver → AMS 创建进程（如未启动）→ scheduleReceiver → onReceive
  └─ 动态 Receiver → 直接通过 Binder 调用 App → onReceive
```

#### 源码关键路径

```java
// AMS.java
```

#### 静态广播（Manifest 注册）

**注册方式：**

```xml
<!-- AndroidManifest.xml -->
<receiver
    android:name=".MyReceiver"
    android:enabled="true"
    android:exported="true">
    <intent-filter>
        <action android:name="android.intent.action.BOOT_COMPLETED" />
        <action android:name="android.net.conn.CONNECTIVITY_CHANGE" />
    </intent-filter>
</receiver>
```

**底层原理：**

```
App 安装时：
  PMS (PackageManagerService) 解析 AndroidManifest.xml
    → 提取 <receiver> 信息
    → 存入 PackageManager 的 ReceiverResolver

广播派发时：
  AMS.broadcastIntent()
    → 从 PMS 查询所有匹配的静态注册 Receiver
    → 如果 App 未启动，先创建进程唤醒 App
    → 通过 IApplicationThread.scheduleReceiver() 派发
    → App 主线程执行 onReceive()
```

#### 动态广播（代码注册）

**注册方式：**

```kotlin
class MainActivity : AppCompatActivity() {

    private val receiver = object : BroadcastReceiver() {
        override fun onReceive(context: Context, intent: Intent) {
            when (intent.action) {
                "com.example.MY_ACTION" -> { /* 处理 */ }
                Intent.ACTION_BATTERY_LOW -> { /* 电量低 */ }
            }
        }
    }

    override fun onStart() {
        super.onStart()
        val filter = IntentFilter().apply {
            addAction("com.example.MY_ACTION")
            addAction(Intent.ACTION_BATTERY_LOW)
        }
        registerReceiver(receiver, filter)
    }

    override fun onStop() {
        super.onStop()
        unregisterReceiver(receiver)  // 必须反注册！
    }
}
```

**底层原理：**

```
registerReceiver() 调用链：
  ContextImpl.registerReceiver()
    → LoadedApk.registerReceiver()
      → ActivityManager.getService().registerReceiver()
        → AMS.registerReceiver()
          → 把 Receiver 信息存入 AMS 的 ReceiverList
          → 返回一个 IntentFilter 列表

广播派发时：
  AMS.broadcastIntent()
    → 从 AMS 的 mRegisteredReceivers 中查找匹配的动态 Receiver
    → 直接通过 Binder 回调 App 的 onReceive()
    → 不需要创建进程（App 必须在运行中才能收到）

反注册：
  unregisterReceiver()
    → AMS.unregisterReceiver()
    → 从 ReceiverList 中移除
    → 不移除会导致内存泄漏（AMS 持有 App 的 Binder 引用）
```

### 无序广播 vs 有序广播

```
无序广播 (sendBroadcast)：
  → 所有 Receiver 同时收到（并行派发）
  → 不能被拦截
  → 不能传递数据给下一个 Receiver

有序广播 (sendOrderedBroadcast)：
  → 按 priority 优先级依次派发
  → 高优先级可以拦截 (abortBroadcast())
  → 可以向下一个 Receiver 传递数据 (setResultData())
  → 优先级范围：-1000 ~ 1000，默认 0
```

```kotlin
// 无序广播
sendBroadcast(Intent("com.example.MY_ACTION"))

// 有序广播
sendOrderedBroadcast(
    Intent("com.example.ORDERED_ACTION"),
    null,           // receiverPermission
    null,           // resultReceiver（最终接收者，不会被拦截）
    null,           // scheduler
    Activity.RESULT_OK,  // initialCode
    null,           // initialData
    null            // initialExtras
)

// Receiver 中拦截有序广播
class HighPriorityReceiver : BroadcastReceiver() {
    override fun onReceive(context: Context, intent: Intent) {
        abortBroadcast()         // 拦截，后续 Receiver 收不到
        resultData = "modified"  // 传递数据给下一个 Receiver
    }
}
```

### Android 8.0+ 的限制

**为什么限制静态广播？**

```
Android 8.0 (API 26) 之前的隐式广播问题：

  隐式广播 = 没有指定具体包名的广播
  → 系统要唤醒所有 App 来检查是否匹配
  → 大量 App 被唤醒 → 内存和电量消耗巨大
  → 每个 App 的静态 Receiver 都可能触发进程创建

Android 8.0 的限制：
  → 大部分隐式广播不再派发给静态注册的 Receiver
  → 只有少数系统广播例外（BOOT_COMPLETED 等）
  → 显式广播（指定包名）不受限制
```

**受影响和不受影响的广播：**

```
被限制（静态注册收不到）：
  ├── CONNECTIVITY_CHANGE（网络变化）
  ├── NEW_PICTURE（新照片）
  ├── NEW_VIDEO（新视频）
  ├── ACTION_PACKAGE_ADDED/REMOVED（应用安装/卸载）
  └── 大部分自定义隐式广播

不受限制（静态注册仍可用）：
  ├── BOOT_COMPLETED（开机完成）
  ├── LOCALE_CHANGED（语言变化）
  ├── ACTION_USER_UNLOCKED（用户解锁）
  ├── USB_DEVICE_ATTACHED（USB 设备连接）
  └── 显式广播（intent.setPackage("com.example")）

解决方案：
  → 改用动态注册 registerReceiver()
  → 改用显式广播 intent.setPackage("com.example")
  → 改用 WorkManager / JobScheduler
```

### 静态 vs 动态 完整对比

| 维度 | 静态广播 | 动态广播 |
|------|---------|---------|
| 注册方式 | AndroidManifest.xml | 代码中 registerReceiver() |
| 注册时机 | App 安装时（PMS 解析） | 运行时调用时 |
| 生存期 | App 进程存活期间 | register 到 unregister 之间 |
| App 未启动能收到吗？ | 能（系统唤醒 App） | 不能（必须先注册） |
| 必须反注册？ | 不需要 | 必须，否则内存泄漏 |
| Android 8.0 隐式限制 | 受限（大部分收不到） | 不受限 |
| 注册位置 | AMS（通过 PMS） | AMS（通过 registerReceiver） |
| 派发方式 | AMS 可能创建进程唤醒 App | 直接 Binder 回调 App |
| 适用场景 | 系统事件（开机、USB） | 运行时事件（网络、电池） |

### 实战层（项目经验）

**onReceive 的限制：**

```
onReceive() 运行在主线程
  → 不能做耗时操作
  → 前台广播 10 秒内必须返回，否则 ANR
  → 后台广播 60 秒内必须返回

做异步操作的方案：
  → goAsync()：获取 PendingResult，最多延长 10 秒
  → WorkManager：可靠后台任务
  → 协程 + 生命周期感知组件
```

```kotlin
class MyReceiver : BroadcastReceiver() {
    override fun onReceive(context: Context, intent: Intent) {
        // goAsync() 获取 PendingResult
        val pendingResult = goAsync()

        CoroutineScope(Dispatchers.IO).launch {
            try {
                // 在后台做耗时操作（最长 10 秒）
                doBackgroundWork()
            } finally {
                pendingResult.finish()  // 必须调用，否则系统认为未完成
            }
        }
    }
}
```

## 记忆锚点

静态广播是"贴在门上的公告"（Manifest 声明，人不在也能贴），动态广播是"面对面递纸条"（register 时才有效，走的时候要拿走）。Android 8.0 之后隐式公告不贴了（限制隐式广播静态注册），防止所有人被吵醒。无序广播是群发消息（并行），有序广播是按座位传纸条（串行，可以拦住不传了）。
